# AgentDeck 全产品页面原型与交互规格书
**版本：1.0｜基线：AgentDeck 最终架构复核与重构决策书 v1.1｜用途：直接交付开发 Agent**

## 0. 产品目标与硬约束

AgentDeck 是 Agent 协作管理平台，不是 Agent Runtime、自动化工作流引擎或 IDE。Agent 负责思考、计划和执行；AgentDeck 负责 Project、Task、Step、Session、Execution、人工决策、版本、影响分析和交付物。

必须遵守：
1. 每个 Agent Session 必须属于一个 Project；不允许脱离项目创建临时 Session。
2. Session 可以不关联 Task。项目内允许探索、讨论和临时想法。
3. 任务树是默认主视图；DAG 仅在存在真实依赖关系时展示，不强制所有任务形成 DAG。
4. 修改 Step 只创建该 Step 的新 Revision；历史版本和执行记录保留；下游步骤标记 `needs_revalidation`，由 Agent/用户判断是否重跑，不自动重跑。
5. UI 只突出任务节点状态、待用户决策和交付物。Agent 思考过程、Token、工具调用流水不进入默认页面。
6. 第一版是合作式管理：Agent 在安全 checkpoint 主动上报，平台承载人工决策；不承诺强制暂停所有外部 Agent。
7. 单用户自托管、SQLite；Windows 为主要运行环境，兼容 macOS/Linux；手机 PWA 访问。
8. 不为旧版永久兼容，但迁移历史数据时不得静默丢弃。
9. 视觉方向：移动端优先、暗色、克制、清晰、单手操作；首页是任务入口，不是大画布或监控大屏。

## 1. 信息架构与导航

### 1.1 主导航
移动端底部 4 个入口：
- **总览**：待我处理、正在执行、最近更新。
- **项目**：项目列表、项目详情、任务树。
- **收件箱**：待决策、待确认、异常提醒。
- **更多**：Agent Sessions、交付物、活动记录、设置。

桌面端采用左侧固定导航 + 主内容区。项目详情和任务详情使用页面内导航，不占主导航位置。

## 2. 全局视觉规范

### 2.1 视觉语言
- 默认暗色主题，深灰蓝黑背景，不使用大面积纯黑。
- 卡片与页面底色有轻微层级差异；边框低对比，不使用厚重阴影。
- 强调色用于主操作；状态色只表达状态。
- 卡片圆角 12–16px，按钮 9–12px。
- 图标统一使用线性图标库；同一语义不混用图标。
- 动效 120–180ms，克制，不闪烁、不大幅位移。
- 中文优先系统字体；文字层级清晰，避免过小字号。

建议 CSS Token：

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#101318` | 页面底色 |
| `--surface` | `#171C23` | 卡片 |
| `--surface-raised` | `#1D242D` | 弹层 |
| `--border` | `#2A323D` | 边框 |
| `--text-primary` | `#E8EDF3` | 主文本 |
| `--text-secondary` | `#A0AAB7` | 次文本 |
| `--text-muted` | `#737F8D` | 辅助文本 |
| `--accent` | `#8BA9FF` | 主操作 |
| `--success` | `#55B88A` | 完成 |
| `--warning` | `#E5AD58` | 待处理/复核 |
| `--danger` | `#E47777` | 失败/阻塞 |
| `--info` | `#72A9D8` | 运行中 |

### 2.2 状态语义

| 状态 | 文案 | 说明 |
|---|---|---|
| `backlog` | 未开始 | 尚未启动 |
| `in_progress` | 进行中 | 当前推进中 |
| `blocked` | 已阻塞 | 需要处理阻塞 |
| `done` | 已完成 | 已验收完成 |
| `cancelled` | 已取消 | 不再继续 |
| `pending` | 待处理 | Step 尚未开始 |
| `needs_revalidation` | 需要复核 | 附加标记，不覆盖原状态 |
| `waiting_decision` | 等待你决定 | Agent 已提交决策 |
| `running` | 执行中 | Execution 运行中 |
| `failed` | 执行失败 | 失败的执行，不等于任务永久失败 |

所有状态必须“图标 + 文案”，不能只靠颜色。一个已完成 Step 可以同时显示“已完成 · 需要复核”。

### 2.3 通用组件
- `PageHeader`：返回/面包屑、标题、简短说明、一个主操作，其余进 `⋯`。
- `StatusPill`：统一状态图标和文案。
- `TaskNode`：展开按钮、状态、标题、进度、待决策/复核标记、更多菜单。
- `StepRow`：序号、状态、标题、版本号、复核标记。
- `DecisionCard`：问题、背景、所属项目/任务、风险摘要、查看并决定。
- `ArtifactCard`：名称、类型、来源任务、版本和时间。
- `EmptyState`：解释为什么为空，并提供下一步操作。
- `Skeleton`：加载时保持页面布局尺寸。
- `Toast`：成功/失败反馈；写操作失败不得清空输入。
- `OfflineBanner`：说明当前离线、数据新鲜度和不可用操作。

桌面端左侧导航 224–248px，主内容最大宽约 1120px；待处理区域优先，可双列展示；不做密集大屏。

桌面端：左侧导航，右侧项目主区；任务树为主体，标题/状态/更新时间可列对齐。主操作“新建任务”，次级“项目设置”；只有存在真实依赖时才显示关系图入口。

任务树规则：
- 默认纵向树；父任务折叠/展开；展开状态记忆。
- 节点包含标题、状态、进度、待决策/复核标记。
- 建议默认显示一级 Task，展开后显示子任务和 Step；项目偏好可调整。
- 点标题进入详情；点折叠按钮只折叠，不跳转。
- 状态筛选：全部、未开始、进行中、阻塞、完成、取消；复核是独立筛选。
- 默认手动排序，可按更新时间/优先级排序。
- 搜索当前项目标题和描述。
- 拖动排序必须有明确模式、把手和保存反馈；改变父子关系需二次确认。
- 新建任务默认根任务，可选父任务。
- 删除采用归档/取消，不做级联物理删除。
- 节点菜单：打开、新建子任务、新建 Step、编辑、改优先级、完成/重开、执行记录、关联 Session、下游影响、归档。

项目会话视图只列当前 Project 的 Session。Task 关联可为空；空关联显示“项目讨论/探索”，不是异常。从项目页创建 Session 自动关联 Project；从任务页创建时自动关联 Project + Task。

四个视图：
- **概览**：标题、状态、优先级、目标描述、总体进度、当前 Step、待决策摘要、最近交付物（最多 3）、关联 Session（最多 3）、下游复核提醒。
- **步骤**：纵向 Step 列表；显示状态、标题、简述、版本、复核标记；点击进入 P06；当前执行步骤轻度突出。
- **动态**：只展示任务/步骤创建修改、Execution 开始/成功/失败/中止、Decision 创建/解决、Artifact 新增、用户决定等业务事件。默认隐藏 Token、工具调用、思考链、stdout/stderr。
- **交付物**：正式 Artifact 列表，显示名称、类型、版本、时间、来源 Step/Execution；临时日志不默认列为交付物。

底部操作：“与 Agent 讨论”为主按钮，“更多”为次按钮。无 Session 时创建新 Session 并自动关联 Project + Task；有活动 Session 时优先继续已有会话，不静默创建重复 Session。待决策卡片优先于底栏，不得被遮挡。

任务菜单：编辑信息、改优先级、完成/重开、新建子任务/Step、查看依赖（有数据时）、执行记录、关联 Session、归档。

```text

│ [实现任务 API                ] │
│ 步骤说明                       │
│ ┌──────────────────────────┐ │
│ │ 实现 Project/Task/Step API│ │
│ └──────────────────────────┘ │
│ 修改原因（可选）               │
│ [接口范围有调整               ] │
│ 保存后：                       │
│ · 当前步骤创建新版本           │
│ · 历史版本和执行记录保留       │

│ · 不会自动重新执行             │
│       [保存新版本]             │
└──────────────────────────────┘
```

若有后续步骤，保存前显示影响预览：当前 Step v1 → v2；列出可能受影响的后续 Step；说明只标记复核、不自动重跑。操作按钮“返回修改 / 确认保存新版本”。

详情显示当前版本、版本历史、修改时间/原因/修改者；旧版本只读。恢复旧版本内容应创建新 Revision，不覆盖历史。Execution 必须标明基于哪个 Step Revision。复核可标记“已复核，无需重跑”或“需要重新执行”。复核不等于失败。

每个 Decision 有唯一 ID、Project、可选 Task/Session/Execution、标题、上下文、选项、风险说明、状态、时间。内容由 Agent 上报，平台展示，不自行推断。默认必须选择一个选项；自由文本按 schema 可选。提交前确认选择和影响；提交成功记录选项、备注、用户、时间和版本。提交失败保留输入；重复提交幂等。已解决只读；重新决策创建新记录。未知影响必须显示“尚未确认”，不可编造。“先补充信息”不等于批准/拒绝。

## 11. P08 收件箱

```text
┌──────────────────────────────┐
│ 收件箱                         │
│ [待我决定 2] [待确认 1] [提醒 3]│
│                              │
│ 需要你决定                     │
│ ┌──────────────────────────┐ │
│ │ ◉ 是否拆分认证模块        │ │
│ │ AgentDeck · 5分钟前       │ │
│ │ 影响 3 个步骤             │ │
│ │ [查看并决定 →]            │ │
│ └──────────────────────────┘ │
│ 待确认                         │
│ ◉ 确认部署目标环境             │
│ 提醒                           │
│ · Step“接口联调”需要复核       │
│ · 最近一次执行失败             │
└──────────────────────────────┘
```

分类：待我决定、待确认、提醒。已处理事项进入历史。默认按紧急程度和时间排序，支持按 Project 筛选。Push 仅用于待决策、执行失败、阻塞、关键交付物；普通 Step 状态变化不推送。通知点击 deep link 到资源详情；不开通知权限不影响使用。

## 12. P09 Agent Session 列表

显示 Agent 名称、Session 名称、Project、关联 Task（可为空）、业务状态、最近活动。筛选全部/活跃/已结束、Agent 类型。新建必须先有 Project；当前项目上下文自动带入；Task 可选。项目级探索 Session 显示“项目讨论/探索”。不显示完整 Prompt、Token。默认不提供物理删除。

## 13. P10 Agent Session 详情

布局：顶部 Agent/Session 名称、Project、Task（可空）、连接状态；中间对话；Decision 结构化卡片；Agent 计划/结果摘要卡片；底部输入框、发送、附件/上下文入口。右上菜单：改名、关联/解除 Task（如允许）、执行记录、结束会话。

Project 归属不能通过普通对话改变。发送消息成功不等于执行成功；Execution 状态独立显示。Agent 离线/连接失败时保留输入并允许重试。默认不展示思考链，只展示 Agent 明确输出的消息和结构化摘要。一个 Session 可有多个 Execution，每次独立记录。

## 14. P11 交付物

列表显示文件名、类型、Project、Task、版本、时间；支持按类型/项目筛选。详情显示摘要、来源 Step/Execution、版本历史、预览（支持时）、下载/复制路径/打开目录（宿主支持时）。后端必须校验路径在 Project root 白名单内；前端不得拼接任意路径。Execution 失败不能自动删除已有 Artifact。

## 15. P12 活动记录

只展示业务事件：Project/Task/Step 创建修改、Execution 开始成功失败取消、Decision 创建解决、Artifact 新增、Session 创建结束/关联变化。默认隐藏 Token、工具调用、思考链、心跳、stdout/stderr。高级诊断从具体 Execution 进入，并标记为技术信息。

## 16. P13 依赖关系图（P2）

只有真实依赖数据时显示入口；任务树始终是默认视图；不从 Step 顺序推断依赖。节点表示 Task/Step，箭头前置→后续；可缩放、拖动、聚焦、点击进入详情。移动端全屏展示，不塞进小卡片。没有依赖时不显示空图。

## 17. P14 设置

分组列表：外观（暗色/跟随系统、密度）、Agent 连接（Agent 状态、测试、默认 Agent）、通知、网络/Tailscale、数据（SQLite 路径、备份恢复导出）、安全（认证、设备访问、超时、危险操作）、关于。密钥不明文回显；敏感配置修改二次确认；数据破坏操作显示影响和备份提醒。

## 18. 状态、实时更新与执行语义

Task 状态：backlog → in_progress / cancelled；in_progress → blocked / done / cancelled；blocked → in_progress / cancelled；done 可重新打开为 in_progress（记录事件）。Step 状态：pending → in_progress / skipped；in_progress → blocked / done / skipped；blocked → in_progress / skipped；done 可重新打开为 pending（记录事件）。后端必须校验状态迁移。

Execution 是一次执行意图；Attempt 是一次实际运行尝试。重试创建新 Attempt，不覆盖旧 Attempt。UI 默认显示 Execution 状态和最近 Attempt 摘要；技术诊断按需展开。取消时显示确认；不支持可靠取消的 Runtime 应显示“正在请求中止”，不能假装已停止。

WebSocket/SSE 只推送状态变化。断线先显示重连状态，再用服务端快照恢复；事件有稳定 ID/序列号，重复事件不能重复创建卡片。页面刷新后待决策和执行状态必须从服务端恢复。

## 19. 移动端规范

- 基准 360px，兼容 320px；左右边距 16px；卡片间距 12px。
- 底部导航 60–68px，适配 iOS Safe Area。
- 触控热区至少 44×44px。
- 任务标题和状态不能依赖横向滚动才能阅读。
- 固定底栏必须给内容留空间。
- 表格转换为卡片/列表。
- 高频操作放在下半屏；顶部只放返回、标题、少量菜单。
- 重要操作不能只依赖长按；拖动排序必须显式进入模式并有把手。
- PWA 离线可读最近缓存的非敏感只读数据（若实现缓存）；离线禁止决策、发送 Prompt、修改任务；恢复网络后由用户重试，不能自动重复副作用操作。

## 20. 桌面端规范

左侧导航固定，项目树作为次级导航。主内容建议 960–1280px，避免超宽文本。任务树/详情可采用主内容+侧栏，但移动端退化单栏。快捷键仅增强，不是唯一操作。桌面可使用系统目录选择器；移动端不假设同等能力。

## 21. UI 数据契约

Project：`project_id/name/description/root_path/archived_at/created_at/updated_at`，汇总 `task_count/in_progress_count/pending_decision_count`。

Task：`task_id/project_id/parent_task_id/title/description/status/priority/sort_order/needs_revalidation`，汇总 `step_count/completed_step_count/active_execution_count/pending_decision_count`。

Step：`step_id/task_id/title/description/status/sort_order/current_revision/needs_revalidation`。

Decision：`decision_id/project_id/task_id?/session_id?/execution_id?/title/context/options/risk_summary/status/created_at/resolved_at`。

Session：`session_id/project_id`（必填）、`task_id?`、`agent_type/display_name/status/last_activity_at`。

Execution：`execution_id/task_id/step_id?/step_revision/status/started_at/finished_at/latest_attempt_summary`。

Artifact：`artifact_id/project_id/task_id?/step_id?/execution_id?/name/mime_type/version/created_at/summary`。

前端不得推断 Agent Runtime 状态，不得根据消息停止到达推断成功，不直接访问 SQLite 或 Agent 内部数据库。决策选项/风险/影响由后端提供。文件访问必须后端授权。

## 22. 空状态、错误和冲突

必须覆盖：无 Project、项目归档、根目录不可访问、项目无任务、任务无 Step、无 Session、待决策、已完成但需复核、Execution 失败、Agent 离线、实时连接断开、决策已被其他页面处理、重复提交、Step 并发 Revision 冲突、归档父任务、文件不可访问。

规则：
- Execution 失败不自动把 Task 变成失败。
- 决策冲突返回服务端真实状态并刷新。
- 双击提交通过幂等键防止重复决策/执行。
- 并发修改不覆盖新 Revision。
- 保存失败保留表单内容。
- 文件访问失败不展示伪造下载链接。
- 项目根目录不可访问时警告，不自动修改根目录。

## 23. 可访问性与产品文案

图标按钮有可访问名称；状态不只用颜色；键盘可操作主要流程；表单错误贴近字段；确认弹窗默认焦点放在安全操作。统一用“需要复核”。区分“消息发送成功”“Execution 成功”“任务验收完成”“Agent 已结束”，不得混用。

## 24. 分阶段开发计划

### Phase A：设计系统与页面骨架
主题 Token、导航、PageHeader、StatusPill、卡片、按钮、弹窗、Toast、Skeleton、Empty State、Offline Banner、路由占位、响应式断点。
验收：所有页面可导航；320/360/768/1280px 无溢出；状态样式统一。

### Phase B：Project / Task Tree
项目选择/创建、项目列表、项目详情、任务树、Task CRUD/状态/排序、Step 列表/创建、API 对接。
验收：Project → Task → Step 创建查看修改并刷新持久化。

### Phase C：Task Detail / Revision
四视图、Step Revision 历史、下游复核标记与处理。
验收：修改只创建新 Revision；下游标记正确；无自动重跑；旧版本可读。

### Phase D：Decision / Inbox
收件箱、决策详情、提交、冲突、历史、Push deep link。
验收：首页/项目/任务/收件箱状态一致；重复提交幂等。

### Phase E：Session / Execution / Artifact
Session 列表详情、项目级/任务级会话、Execution/Attempt 摘要、Artifact、离线/连接状态。
验收：Session 必须归 Project；Task 可选；Attempt 不覆盖；Artifact 可追溯。

### Phase F：高级页面
活动记录、依赖图、设置、高级诊断。
验收：高级功能不影响核心流程；无依赖不显示空图；诊断与业务活动分开。

## 25. UI 验收用例

1. 无 Project 首次进入创建引导；创建后进入项目详情。
2. 刷新保持 Project 上下文；不允许无 Project 创建 Session。
3. 创建根任务、子任务、Step；展开/折叠；状态修改刷新保持。
4. 移动端节点标题进入详情，折叠按钮不跳转。
5. 搜索/筛选/排序；拖动失败恢复原顺序。
6. Step 编辑产生新 Revision；旧版本只读；下游需复核；不自动执行。
7. Decision 出现在总览和收件箱；显示影响；提交后 resolved；重复提交幂等。
8. 从项目创建 Session 自动关联 Project；从任务创建关联 Project+Task；项目探索 Session 可不关联 Task。
9. Execution 失败不改变 Task 状态；Attempt 重试保留历史。
10. 320px 无横向溢出；iOS Safe Area 正常；热区≥44px；桌面侧栏正常；键盘可操作；离线写操作受阻。

## 26. 交付开发 Agent 的执行指令

1. 先审查仓库，不要直接重写：检查前端框架、路由、样式、API、WebSocket、PWA、测试和构建。
2. 本文档与《AgentDeck 最终架构复核与重构决策书 v1.1》共同构成基线。
3. 先输出页面/组件与现有文件映射表，再编码。
4. 按 Phase A–F 顺序实施，每阶段独立提交和测试。
5. 页面、领域组件、共享组件分层，不要把所有页面堆进单一组件。
6. Mock 必须明确标记，交付前替换真实 API。
7. 不得伪造执行状态、决策结果、Artifact 或文件权限。
8. 默认 UI 不展示思考链、Token、工具调用流水。
9. 不强制 DAG，不自动推断依赖，不因 Step 修改自动触发下游。
10. 所有写操作有 loading/success/error/conflict 反馈。
11. 每阶段交付：变更文件清单、实现说明、测试命令及结果、未完成项、截图。
12. 移动端 360px 和桌面 1440px 都要提供真实页面截图，尤其任务树和任务详情。
13. 不修改 `main`，只在指定功能分支开发。
14. 与后端 API/数据模型冲突时先报告差异，不得默默猜测。

## 27. 与架构决策书的关系

架构决策书 v1.1 决定产品边界、领域模型、后端技术和 Agent 接入原则；本文档 v1.0 决定页面信息架构、视觉风格、布局、交互和 UI 验收。若页面需求与领域不变量冲突，以架构决策书为准；若实现与交互规则冲突，应调整实现，不得擅自改变用户体验目标。

本文是可执行的产品/UI 规格，不代表真实前端原型已编码或通过浏览器测试。真实截图和交互测试由开发阶段产出。
